0事前コード整備(開発機・すべてコミット済み)

本番化に伴い必要になったコード修正。先に全部入っておくとサーバー側は迷わない:

修正理由
STATIC_URL="/static/"(絶対)+STATIC_ROOT相対URLだと /accounts/login/ 等でCSSが404。collectstaticの出力先定義
core/protected_media.py + urlsのDEBUG分岐DEBUG=0で/mediaが死なず、ログイン限定で配信されるため
if not DEBUG: の https強化(SECURE_PROXY_SSL_HEADER/CSRF env/secure cookie)nginxプロキシ越しhttpsとPOST CSRFの成立
apps.py _is_wsgi_server_process()gunicornでAI常駐が起動しなかった本命(RUN_MAINはrunserver専用トークン)
検知プローブ⇔acquire対称抑止(probe_running/_opening)同index二重open→MSMFゾンビ化の連鎖遮断(開発機で実害確認)
requirements.txt に torch/torchvision(+cpu)+transformersLinux本番でもCLIP検証官が生きているように
環境バッジ(CARE_SEC_ENV)+AISettings.camera_source開発/本番の取り違え防止とカメラ源ツマミ

1AWS基盤(コンソール)

1.1 VPC

デフォルトVPC(172.31.0.0/16)をそのまま使用。単一公開サーバーには専用VPC/NAT不要。

1.2 セキュリティグループ(新規 caresec-web)

タイプポート送信元
HTTP/HTTPS80, 4430.0.0.0/0(公開窓口)
SSH22自分のIP/32のみ(0.0.0.0/0禁止)
カスタムUDP518200.0.0.0/0(WireGuard。鍵認証済みしか通らない)
8554(RTSP)は開かなかった。Pi→EC2はトンネル内(10.8.0.x)だけを流れ、公网に映像ポートは存在しない。

1.3 EC2起動

  • AMI: Ubuntu 26.04 LTS / type: t3.large / EBS: 30GiB gp3 + 暗号化(aws/ebs) / 終了時に削除=いいえ / タームネット保護=有効
  • キーペア: 新規 caresec-key(.pem をダウンロード)
  • ユーザーデータ=ガイド6.2スクリプト(JST・apt・nginx・swapon 4G・unattended-upgrades・caresecユーザー)

1.4 Elastic IP

同じリージョンでEIPを割当→インスタンスに関連付け。以後IPは不変(自動パブリックIPは置き換わる)。

3.4 DB/静的/systemd(gunicorn workers=1必須)


sudo -u caresec bash -c "cd /srv/caresec && .venv/bin/python manage.py migrate && .venv/bin/python manage.py collectstatic --noinput"

[Unit]
Description=CARE SEC (Django + AI engine)
After=network-online.target
[Service]
User=caresec
Group=www-data
WorkingDirectory=/srv/caresec
EnvironmentFile=/etc/care-sec.env
ExecStart=/srv/caresec/.venv/bin/gunicorn config.wsgi:application \
  --bind 127.0.0.1:8000 --workers 1 --threads 8 \
  --timeout 120 --graceful-timeout 30 --access-logfile - --error-logfile -

RestartSec=5
[Install]
WantedBy=multi-user.target
EOF

4nginx + メディア保護

sudo tee /etc/nginx/sites-available/caresec >/dev/null <<'EOF'
server {
    listen 80;
    server_name caresec.duckdns.org <EIP>;
    location /static/ { alias /srv/caresec/staticfiles/; expires 7d; access_log off; }
    # /media/ は静态配信しない(Djangoのprotected_mediaがログイン判定後に返す)
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s; client_max_body_size 50m;
    }
}
EOF
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/caresec /etc/nginx/sites-enabled/caresec
sudo nginx -t && sudo systemctl reload nginx
サーバー名にドメインとIPの両方を最初から書いておくと、後段のcertbotが「一致するブロック」を見つけられる(実走で一度はまった)。

5HTTPS(DuckDNS無料 + certbot)

# 1) https://www.duckdns.org で caresec.duckdns.org → EIP を登録(current ip=EIP!)
# 2) EC2:
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d caresec.duckdns.org
#    失敗: "Could not automatically find a matching server block"
#    解決: server_name にドメインを追記して reload → certbot install 再実行
sudo sed -i 's/server_name <EIP>;/server_name caresec.duckdns.org <EIP>;/' /etc/nginx/sites-available/caresec
sudo nginx -t && sudo systemctl reload nginx
sudo certbot install --cert-name caresec.duckdns.org   # Redirect=2

# 3) 検証
curl -s -o /dev/null -w "%{http_code} → %{redirect_url}\n" http://caresec.duckdns.org/   # 301 → https
curl -s -o /dev/null -w "%{http_code}\n" https://caresec.duckdns.org/accounts/login/      # 200
systemctl list-timers | grep -i certbot            # 自動更新timer生存
sudo certbot renew --dry-run                        # 稽古成功

8実走で踏んだ罠と解決(教訓集)

罠症状解決
gunicornでAI不启动Webは動くのにjournalctlに[RealtimeAI]ゼロ_is_wsgi_server_process()追加(RUN_MAINはrunserver専用)
Python 3.14既定TF/mediapipeのwheelが無いdeadsnakesで3.13導入。venvだけ3.13、システムpythonは触らない
torchの+cpuPyPIに+cpu版は存在しない--index-url https://download.pytorch.org/whl/cpu を分段で
STATIC_URL相対loginページだけCSS404"/static/"絶対+STATIC_ROOT+collectstatic
certbot install失敗証明書は取れるのに「matching server blockなし」server_nameにドメイン追記→reload→certbot install再実行
DuckDNS初期IP自分のPCのIPが自動入力されるcurrent ipをEIPにupdate ip
MediaMTX includeERR json: unknown field "include"pathsは本体ymlへマージ(include構文なし)
/usr/local/src DLPermission denied/tmpでDL→sudo tar展開
ustreamerの404/mjpg/が無い正解は/stream(indexのhrefを信じる)
サーバー二重起動index1「他のデバイスが使用中」runserverは常に1個。systemd環境は元々1個
検知⇔acquire二重openMSMFゾンビスレッドがC270を握り続け全open失敗probe_running/_opening対称抑止+サーバー再起動でゾンビ消去
vcgencmd get_camerasupported=0と出て誤認新OSでは廃止。libcameraのRegistered行が真相
HEADでcontent-type確認/streamがtext/htmlと誤答GET+head -c 200でboundary/JFIFを見る
多行コマンドペースト^[[200~混入でcommand not found1行ずつ実行/bracketed-paste off
次回のための最短教訓: ①サーバーは1個 ②カメラのopen競合は対称ガード ③gunicorn=workers1 ④Python3.13 ⑤certbot前にserver_name確認 ⑥バックアップは動き出す前に
